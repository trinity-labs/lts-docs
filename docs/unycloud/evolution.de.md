# Entwicklungen
`UnyCloud` entwickelt sich durch die Konsolidierung von drei Achsen: Laufzeit, Branding und Zugriffsverhalten.

## Klarere Laufzeit
UnyCloud Runtime hält die Filebrowser-Kompatibilität: Binär kann unter Name installiert bleiben `filebrowser`Die Basis und die Konfiguration bleiben kompatibel, während der Build auch ein Artefakt erzeugt. `dist/unycloud`.

## Branding plus Produkt
Der Übergang von einem rohen Filebrowser zu einer UnyCloud-Oberfläche erfordert:

- Ein stimmiges Logo
- Ein dediziertes CSS
- Kontrollierte Bilder
- Eine klare Unterscheidung zwischen Aussehen und Login-Logik

## Wichtiger Proxy
Die Anmeldehistorie zeigte, dass der Proxy nicht nur ein Tunnel ist, sondern zur zuverlässigsten Korrekturschicht werden kann, wenn der SPA nicht genügend Kontrolle über das endgültige HTML gibt.

## Ehrgeizigere Härten
Die jüngste Entwicklung bringt UnyCloud über das einfache Branding hinaus: strenges CSP, Entfernen inkompatibler Frontend-Pfade, sicherere Vorschauen, Abfragelimits, Server-Cookies, Sicherheitsprotokolle und Fail2Ban-Integration.

## Nächste Richtung
Die natürlichen Entwicklungen sind:

- Bessere Dokumentenzugriffsprofile und -perimeter
- Share Workflows klären
- Machen Sie Gesundheitschecks sichtbarer
- Halten Sie eine Admin-Dateibrowser-Dokumentation mit der öffentlichen Oberfläche von UnyCloud in Einklang
