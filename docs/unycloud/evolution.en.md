# Developments
`UnyCloud` evolves by consolidating three axes: runtime, branding and access behavior.

## Clearer Runtime
UnyCloud runtime keeps Filebrowser compatibility: binary can remain installed under name `filebrowser`, the base and configuration remain compatible, while the build also produces an artifact `dist/unycloud`.

## Branding plus product
The transition from a raw Filebrowser to a UnyCloud surface requires:

- A coherent logo
- A dedicated CSS
- Controlled images
- A clear distinction between appearance and login logic

## More important Proxy
The login history showed that the proxy is not just a tunnel. It can become the most reliable correction layer when the SPA does not give enough control over the final HTML.

## More ambitious hardening
The recent trajectory pushes UnyCloud beyond simple branding: strict CSP, removal of incompatible frontend paths, safer previews, query limits, server cookies, security logs and fail2ban integration.

## Next direction
The natural evolutions are:

- Better document access profiles and perimeters
- Clarify share workflows
- Make health checks more visible
- Keep an admin Filebrowser documentation aligned with the UnyCloud public surface
